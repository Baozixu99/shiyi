# 拾忆 · 第二轮线上复测与优化建议

**发布判断：本轮测试建议暂缓推广，先修多标签覆盖收藏。** 上一轮的无效链接假成功、分段丢失、原文搜索失败等问题已有明显改善。当前最严重的缺陷有更精确的触发条件：用户同时开着两个首页，即使先后提交、两次都显示成功，第二份收藏也可能覆盖第一份。

2026-11-24，在[同一个线上地址](https://37ljkvjqby7ib89amxv.traesite.cn)重新测试。主测和三名分工 Agent 走可见 UI，用新材料操作。关键写入实验等其他 Agent 停止写入后，由一人按固定顺序执行。页面未提供本轮可确认的构建编号。以下结论限定于此次访问和列明的场景。

## 优先交给 TRAE 的工单

### R2-01 · P0 · 两个标签先后收藏，两篇文章变成同一个报告

| 顺序 | 操作 | 实际结果 |
|---|---|---|
| 对照 | 其他 Agent 停止写入。单标签提交可分析的「金穗装订」长文，等成功后刷新 | `#/report/cap-108` 仍是金穗，知识卡和 D0 状态都在 |
| 1 | 在同一浏览器提前打开首页 A、B | 两个标签各显示 7 张到期 |
| 2 | A 提交「灰鲸胶片编号」，等到报告和卡片已生成 | 地址 `#/report/cap-110`，8 张到期 |
| 3 | 保持 B 原样，B 提交「银杏标本收纳」，等到报告和卡片已生成 | 地址也是 `#/report/cap-110`，仍为 8 张到期 |
| 4 | 回 A 刷新，再打开收件箱 | 原地址标题已变成「银杏标本收纳」。收件箱找得到银杏，找不到灰鲸。两篇均成功、各有一张新卡，预期此时应为 9 张到期 |

并行探索阶段也出现过同类现象：器材报告刷新后，同一地址变成另一个测试标签提交的无效链接。上表复现不要求同时点击，也不依赖任务正在生成。[A 提交成功](QA-round2/06-tab-A-before.jpg) · [B 提交成功](QA-round2/07-tab-B-same-url.jpg) · [A 刷新后的结果](QA-round2/08-tab-A-after.jpg) · [单标签对照](QA-round2/05-solo-real-after-refresh.jpg)

**开发排查。** 查材料和卡片 ID 的分配位置、持久化的写入粒度，以及已打开页面是否会把旧状态写回。仅更换 ID 仍有可能丢掉另一标签新增的记录。保证每次提交生成独立稳定的 ID，只提交本次变更；并发修改同一对象时要能发现版本冲突。采用现有存储架构即可。

**关单条件。** A→B 和 B→A 两种顺序都走通，两份报告地址不同，任一标签刷新或重开都能读到各自原文。收件箱增 2、卡片增 2、到期数增 2。再测 A 给某张卡评分、B 从旧页面新建另一条收藏，评分和新增都必须保住。最后回归同页双击只产生一条，防止把“两个独立提交”和“一次误双击”混在一起。

### R2-02 · P1 · 首页以 60 字拒绝了能直接回答问题的方法

同一份 **57 字**材料，首页显示「未能获取可分析的正文」「正文太短（不足 60 字）」，报告还写「快照未留存」。实验室保留全文，V1 判「值得读」，V4 对“哪一步做完才能压紧夹条”明确回答“对照目录查缺页并确认无误后”，还给出原文入口。[首页失败](QA-round2/04-solo-after-refresh.jpg) · [实验室成功](QA-round2/09-short-lab.jpg)

> 金穗装订核对。两人装订资料时，一人按页码摆放，另一人对照目录检查缺页，检查无误后才压紧夹条。最后登记本册检查日期。

**建议与验收。** 分开表示“没有拿到正文”和“已拿到但信息可能不足”。对主动粘贴的短文保留原文；包含明确事实、条件、步骤的短文应可判断。用上述 57 字流程、短广告、一句改地点通知、纯空白作对照。流程提取可执行步骤；广告建议跳过；通知直接展示地点；空白在表单端拦截。

### R2-03 · P1 · 给失败链接补正文后，材料失去原来源

提交无效链接 → 在失败报告点「粘贴正文重新分析」→ 提交一段正文。原失败链接仍留在收件箱，新结果另列为「粘贴文本」。从界面看不出补录内容与原链接有关。这次无效链接本身已正确拦截，待复习保持 5 张。[两条记录并列](QA-round2/import-inbox-recovery-separate.jpg) · [原失败报告](QA-round2/import-invalid-no-card.jpg)

**建议与验收。** 默认将补录正文附到发起补录的收藏上，保留来源、原报告地址和「用户补充正文」标识；若内部用新版本，旧入口应能找到新结果。用失败链接补一份有效方法，前后只占一个收藏位置，成功后只产生预期卡数，刷新后也能从原入口追溯。

### R2-04 · P1 · 引文标记改善了，知识卡仍会改动数量或预测条件

两篇材料提供了具体反例：

- 借伞记录写「上周只有两个雨天」。一次 V1 要点改成「两周雨天样本不足」，把雨天数量变成周数。相同正文第二次返回正确。此为重复两次出现一次的内容错误。[第一次的要点](QA-round2/lab-01-umbrella-summary.jpg)
- 上轮同一篇公众号，这次首页正确把改写标为「摘要 · 非逐字原文」。但快照是「最快在 2027 年」，卡片写成「Pachocki 预测2027年出现」，丢掉了最早时间限定。卡片标题只留下 0.68，原文对临界区的描述是 0.68 到 0.70。[首页知识卡](QA-round2/10-wechat-summary.jpg)

**建议与验收。** 提炼要点时把“数字＋单位＋对象＋观察周期或限定词”作为一组绑定原句。先检查进入复习的标题和要点。样本至少包含“上周的两个雨天”“最快在 2027 年”“比如 0.68”“0.68 到 0.70”。无法核对时可以少生成一个要点。允许模型换措辞，验收针对含义。

### R2-05 · P2 · 编辑目标期间，旧答案仍标为本轮结果

展板材料第一次问“正好 90 厘米应走哪个门”，系统回答东门。只把目标改为“是用重量还是宽度决定”，尚未提交，旧答案旁仍写「本轮提交」，也看不到生成它时的旧目标。真正发起新请求后，页面已有“下方结果属于上一次提交”的提示。[草稿与结果](QA-round2/lab-03-goal-edited.jpg)

**建议与验收。** 结果保留提交时的材料标识和目标。任一项编辑后立即提示「输入已修改」；旧结果展示原目标。测试只改目标、只改正文、改完撤回、重跑失败四种状态。

### R2-06 · P2 · 复习成绩保存了，刷新后本轮进度清零

在其他标签停止写入时，给自建银杏卡评「记住」：页面显示 D0→D1、已完成 1/8、作答 1 次。立即刷新变成 0/7、作答 0 次，下一张题没变。卡片库确认银杏仍为「D1 · 未到期」。普通跨页再后退能保留会话进度。多人并行测试期间还观测过 D7 回退到 D3，应与 R2-01 联动回归。

**建议与验收。** 区分每日已完成、剩余卡、当前练习的作答次数。优先支持刷新继续同一轮；若产品定义为新开一轮，至少能看出今天已完成 1 张、还剩 7 张。覆盖一次「忘记」后刷新和队尾重练。

## 产品优化 · 先把实验室已跑通的体验带到首页

1. **给用户一个与目标有关的结论。** 同一份展板材料，问“正好 90 厘米走哪扇门”，V4 回答东门并给出处；问“押金是多少”，V4 明确说原文没提，建议跳过。这比通用的“信息密度高”更能帮用户决定是否阅读。正式入口保留一键提交，允许选填“我想知道什么”；有目标时，首屏优先显示答案或明确缺少的信息。[命中原句的例子](QA-round2/lab-02-umbrella-evidence.jpg)
2. **一次性通知直接给行动信息。** 通知样本被认出是地点变更，收件箱仍写「无阅读价值」。建议显示“扫一眼即可”，把时间、地点、入口提到首屏，保留原文且默认不加复习。以收到通知后无需打开报告也能走到正确地点为验收。[通知实测](QA-round2/import-notice-report.jpg)
3. **让每次复测能对应一个发布版本。** 在实验室或关于页展示短版本号。自测记录同时保存版本、材料标识、阅读目标和结果，后续能区分模型波动、规则变更与前端回归。

本轮未测试真实 iOS/Android、跨账号或跨设备、真实跨日调度、30 天到期、后台数据落盘。首页附件入口仍明确标为模拟；本轮没有真实文件上传结论。双标签结论来自同一浏览器、同一站点，未推断跨用户影响。
