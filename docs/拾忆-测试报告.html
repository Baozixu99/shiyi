03 · 缺陷清单与修复

D1 · 报告页缺少原文快照溯源入口 已修复

现象：「快照已留存」只是纯文本，ACTIONS 里的 openSnapshot 处理器从未被任何模板引用；且对 snapshot:false 的条目（抓取受限）文案失实。

修复：app.js renderReport() — snapshot 为 true 时渲染可点击的「原文快照已留存 · 点击溯源」link-btn；为 false 时显示「快照未留存」。

D2 · 卡片弹窗「归档 / 删除」点击崩溃 已修复 · 严重

现象：点击后控制台 Uncaught TypeError: Cannot read properties of undefined (reading 'status')。根因：弹窗底部按钮未携带 data-id，事件委托传给 DB.cardById(undefined)。归档、恢复、删除三条路径全部不可用。

修复：app.js renderCardModalBody() — 归档与删除按钮补上 data-id。编辑/分享/重新提炼因使用模块级 modalCardId 本就正常。

D3 · 分享链接 ID 截断 已修复

现象：c.id.slice(-6) 把 card-01 截成 ard-01。

修复：app.js L521 — 改为 c.id.replace(/^card-/, 'c')，链接变为 https://shiyi.app/s/c01。

D4 · 单条丢弃缺少二次确认 已补齐

现象：批量丢弃有 3 秒确认窗口，单条「丢弃」却是瞬时执行，交互不一致且误触成本高（虽有 30 天回收站兜底）。

修复：app.js decideFlow() — 单条丢弃复用 confirmDrop(1)，确认 toast 文案改为通用「3 秒内再次点击『丢弃』确认」。
