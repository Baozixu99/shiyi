拾忆 · 产品需求文档

把「收藏了就吃灰」的内容，变成「会被记住」的知识卡片。

1背景与目标

用户日常在浏览器中消费大量碎片化内容：公众号文章、小红书笔记、长篇技术文档、图片、视频链接等。其中混杂着大量 AI 生成的低营养文章与营销软文，也夹杂着真实有价值的内容。用户的默认应对方式是「收藏」，但收藏夹往往从此不再被打开——收藏 ≠ 掌握。

问题链：用户遇到值得保存的内容 → 收藏 → 从不回顾 → 内容真正失效、收藏夹吃灰
产品响应：提供一条「丢入 → AI 判定与提炼 → 知识卡片 → 按遗忘曲线复习」的闭环，让用户收藏的内容被真正消费和记住。

目标（可观察结果）：

  • 用户在浏览器中遇到任何内容时，能在不离开当前页面的情况下将其丢入收件箱；
  • 丢入的内容会得到一份 AI 价值判定与理由，有价值的内容被自动提炼为知识卡片；
  • 用户每天可以完成当日到期的复习，复习完成的卡片进入「已巩固」状态，不再占用每日注意力。

本产品为个人工具，不做协作与社交信息流；商业化模式不在本文档范围内（见开放问题）。

2产品契约

要素定义
主要用户有「收藏夹吃灰」困扰的个人内容消费者：公众号读者、小红书用户、技术文档读者。单一角色：收藏者本人；分享页的查看者为只读访客，不构成独立角色。
触发用户在浏览器中遇到想保存的内容（网页、选中文本、图片、文档），通过插件一键丢入收件箱；或在 Web 端粘贴 / 拖拽上传。
核心任务把「收藏了但不会再看」的内容转化为「会被记住」的知识卡片，并通过复习计划被真正掌握。
完成条件内容被判定并提炼为知识卡片且进入复习计划；用户按计划完成全部复习间隔后，卡片进入「已巩固」状态。
共享业务对象收藏内容（Capture）→ 知识卡片（Card）→ 复习计划（ReviewSchedule）→ 复习记录（Review）。全部归属单一用户账户。
后果性动作与信任① 丢弃内容与删除卡片：仅由用户显式确认触发，进入回收站且可恢复（规则 R2）。② 公开分享卡片：用户显式开启才生成公开链接，可随时关闭（FR-08）。AI 永远不自动删除用户内容。

3范围

最小完整旅程（P0）

  • 入口条件：用户已登录账户，插件已安装。
  • P0 动作：丢入内容（FR-01）→ AI 处理与判定（FR-02）→ 低价值内容用户确认（FR-03）→ 生成知识卡片（FR-02/04）→ 卡片库管理（FR-05）→ 每日复习（FR-06/07）。
  • 完成证据：收件箱中每条内容都有明确去向（已转化 / 已丢弃 / 待确认 / 失败可重试）；每日复习队列可以被清空。
  • 关键恢复路径：AI 处理失败的内容可重试；抓取受限的内容允许用户粘贴正文继续处理（FR-01）；丢弃与删除均可从回收站恢复（R2）。

P1（明确后续，不阻塞 P0）

  • 记忆宫殿复习模式：将卡片放置到一个可视化的空间（如房间、路线）中的位置，复习时沿空间漫游，借助空间记忆辅助回忆。交互形态需在 P1 启动前专项定义（见开放问题）。复习结果回写同一套艾宾浩斯计划（R1）。
  • 多端同步（移动端）：手机端查看卡片与复习；不作为首个版本范围。

排除项（非目标）

移动端 App（P0 不做） 团队协作 / 多人空间 社交信息流 / 内容推荐 跨用户内容市场 写作 / 笔记编辑器 AI 自动删除用户数据

排除「自动删除」：与用户确认的决策一致（见 §2 后果性动作），AI 判定为低价值的内容永远只是「待确认」，不会消失。

4核心对象与状态

4.1 对象模型

对象含义关键字段
收藏内容 Capture用户丢入的原始内容内容类型（链接 / 选中文本 / 图片 / 文档）、来源 URL、原文快照、收集时间、AI 判定结论与理由、处理状态
知识卡片 CardAI 从有价值内容中提炼的核心知识一句话总结、核心要点（3–5 条）、关键摘录、来源链接、主题标签、判定理由
复习计划 ReviewSchedule卡片的艾宾浩斯复习安排当前间隔阶段、下次复习时间、累计复习次数、是否已完成
复习记录 Review一次复习的反馈卡片、反馈（记住 / 模糊 / 忘记）、复习时间、反馈后的间隔变化

4.2 收藏内容（Capture）状态机

待处理→ 处理中→ 已转化（生成卡片）
处理中→ 判定为低价值 → 待确认→ 已丢弃（入回收站）或 强制保留 → 已转化
处理中→ 失败 → 待重试→ 重新处理
当前状态允许的操作禁止的操作
待处理 / 处理中查看详情、取消处理编辑、丢弃
待确认（低价值）丢弃、强制保留生成卡片、批量操作直接删除原文（必须经确认动作）
失败 / 待重试重试、粘贴正文补充、丢弃—
已转化跳转到卡片、归档原文重新生成（除非用户手动重试 AI）

4.3 知识卡片（Card）状态机

正常（学习中）→ 已巩固（完成全部间隔）→ 归档（用户手动）

卡片生成后即为「正常」状态并立即进入复习计划（不做草稿确认环节——AI 判定有价值即直接转化，减轻用户负担；卡片随时可编辑）。归档与删除进入回收站，可恢复（R2）。卡片被删除时，其复习计划一并终止。

5功能需求

FR-01 · 内容收集

浏览器插件 + Web 端收集入口

目的：让用户在遇到内容的当下、不离开当前页面，就能把内容丢入收件箱——这是整个旅程的入口，摩擦必须最小。

触发与入口

入口支持内容操作方式
插件右键菜单网页链接、选中文本、图片右键 →「拾忆 · 收藏此内容 / 收藏选中文本 / 收藏此图片」
插件弹窗任意粘贴的链接 / 文本点击插件图标 → 粘贴 → 提交
Web 端上传文档（PDF / TXT / Markdown / Word [Assumption, TBD]）、图片、链接、纯文本拖拽或粘贴上传

处理规则

  • 提交后立即返回成功反馈（toast「已加入收件箱」），处理在后台异步进行（见 FR-02）。
  • 收集时保存原文快照（规则 R4），以保证原文失效后卡片仍可溯源。
  • 同一条 URL 重复收集时，提示「此内容已在收件箱 / 已有卡片」，不产生重复条目。

异常

  • 抓取受限（需登录、付费墙、反爬页面）：内容标记为「抓取受限」，插件浮层引导用户「选中正文文字再收藏」，选中文本路径不受此限制。
  • 未登录提交：插件暂存最近一次提交（本地），引导登录后自动补交。
FR-02 · AI 内容处理

价值判定 → 核心提取 → 卡片生成

目的：替用户完成「读什么、值得吗、重点是什么」的判断，产出可直接复习的知识卡片。

触发

内容进入收件箱后自动开始，无需用户操作。处理状态（处理中 / 完成 / 失败）在收件箱条目上实时可见。

处理链

抓取 / OCR / 文档解析→ 原文快照（R4）→ 价值判定→ 核心提取→ 卡片生成

分析报告 · 产品入口体验

分析判定是本产品的入口时刻（评审共识）：处理链在收件箱条目上可视化展示（抓取 → 通读全文 → 价值判定 → 要点提炼，逐步点亮，让 AI「干活」看得见）；处理完成后以分析报告页呈现结果——判定结论（值得读 / 不建议读）、判定理由、内容类型标签与核心要点预览，视觉上为第一屏主角而非一条附带通知。分析报告页是后续所有动作的出发点：卡片查看/编辑、进入复习、内容裁决均从报告页发起。

价值判定输出

字段说明
结论有阅读价值 / 无阅读价值（两值，不做中间等级，避免判定抖动）
判定理由1–2 句话，向用户说明「为什么值得 / 不值得读」，是用户确认环节（FR-03）的决策依据
内容类型标签如：技术文档 / 观点文章 / 教程 / 资讯 / 营销推广 / AI 水文（标签集 [Assumption, TBD]，可迭代）

结果分流

  • 判定为有价值：直接生成知识卡片并进入复习计划，字段为——一句话总结、3–5 条核心要点、关键原文摘录、来源链接、AI 主题标签、判定理由；生成无需用户二次确认（评审共识），分析报告页即时提供「查看 / 编辑卡片」与「开始今日复习」入口。
  • 判定为无阅读价值：不生成卡片，进入「待确认」队列，等待用户裁决（FR-03）；分析报告页同时提供「丢弃 / 强制保留 / 前往待确认」三种裁决入口。AI 不做任何删除。
  • 处理失败：自动重试 1 次（R3），仍失败则进入「待重试」，通知用户。

异常

  • 图片无法识别有效文字时，判定失败并提示用户改用文档 / 文本形式提交。
  • 超长文档（如上百页 PDF）只提炼卡片不截断丢弃，处理时长在条目上明示。

FR-03 · 低价值内容确认

用户裁决 AI 判定为「无阅读价值」的内容

目的：AI 只建议、用户裁决。既过滤噪音，又保证用户对自己的收藏有最终控制权（§2 后果性动作）。

触发

FR-02 判定为「无阅读价值」的内容进入 Web 端「待确认」列表，条目展示：内容预览 + AI 判定理由 + 内容类型标签。

用户操作

操作结果
丢弃内容移入回收站（R2，30 天可恢复），不生成卡片
保留覆盖 AI 判定，仍生成知识卡片并进入复习计划
忽略留在待确认列表；滞留超过 7 天自动移入回收站 [Assumption, TBD]，回收站内可恢复
  • 支持批量丢弃 / 保留；批量丢弃前显示影响数量并要求二次确认。
  • 用户「保留」的判定会作为信号反馈给后续判定（产品决策：同类内容的误判率是判定质量的重要观测点，机制细节 TBD）。
FR-04 · 卡片查看与编辑

知识卡片的编辑与生命周期管理

触发

卡片生成后（含 FR-03 强制保留路径），用户在卡片库中打开任意卡片。

规则

  • 卡片全部字段（总结、要点、摘录、标签）可编辑；编辑不重置复习进度（共享决策）。
  • 卡片详情页提供原文溯源：跳转原始链接，链接失效时展示原文快照（R4）。
  • 用户可归档卡片（暂停复习、移出队列）与删除卡片（入回收站，R2）。
  • 用户可对卡片手动触发「重新提炼」（AI 重跑），重跑覆盖 AI 生成字段，不覆盖用户编辑过的字段（字段级保护 [Assumption, TBD]）。
FR-05 · 卡片库

知识卡片的组织与浏览

规则

  • 浏览维度：按收集时间、按主题标签、按来源（链接域名）；支持全文搜索（搜卡片内容与原文快照）。
  • 标签体系：AI 自动打标为主，用户可增删改；卡片可属多个标签。
  • 卡片库首页展示状态概览：学习中 / 今日待复习 / 已巩固 / 归档，四个计数。
  • 空状态：新用户卡片库为空时，引导「先去丢入第一条内容」（链接到收件箱）。
FR-06 · 艾宾浩斯复习系统

每日复习队列与间隔反馈

目的：把「收藏」变成「记住」。复习是这个产品的核心闭环——没有复习，前面的提炼都没有意义。

触发

用户打开 Web 端「今日复习」页面；或收到复习提醒（FR-07）。

复习流程

  1. 展示卡片正面：一句话总结（用户先主动回忆）；
  2. 用户点击翻面：查看核心要点与摘录，自评记忆效果；
  3. 用户给出反馈：忘记 / 模糊 / 记住 三选一；
  4. 系统按规则 R1 调整该卡片的下次复习时间，并进入下一张。

规则

  • 每日队列只显示今日到期的卡片，顺序按到期时间升序 [Assumption, TBD]；队列清空即当日复习完成。
  • 间隔反馈实时生效，跨端同步（FR-09）。
  • 复习页面始终展示队列进度（第 x / n 张）与今日统计。

异常

  • 复习中断（中途关闭页面）：已提交的反馈已生效，未复习的卡片保留在队列中，下次进入继续。
  • 逾期未复习：过期卡片顺延到下一天，不做惩罚性堆积限制；连续逾期卡片在统计区以「逾期」计数提示 [Assumption, TBD]。
  • 队列过载：单日到期超过 50 张时，允许用户「今日先复习 20 张」，剩余顺延 [Assumption, TBD]。

FR-07 · 复习提醒

让用户回到复习队列

规则

  • 提醒渠道：浏览器通知（插件侧，需用户授权）+ Web 端打开时的顶部横幅。最终渠道组合与提醒时间 TBD（见开放问题）。
  • 提醒内容固定为行动导向：「今日有 n 张卡片待复习」+ 一键进入复习页。
  • 用户可全局关闭提醒；关闭后 Web 端横幅仍保留（不构成打扰）。
  • 当队列中没有到期卡片时，不发送提醒。
FR-08 · 轻分享

卡片的公开只读链接

触发

用户在卡片详情页显式点击「生成分享链接」。

规则

  • 分享页为公开只读：展示卡片内容（总结、要点、摘录）与原文来源；不暴露用户的其他卡片与账户信息。
  • 默认关闭；仅对被分享的那一张卡片生效，不影响其他卡片。
  • 用户可随时关闭分享链接，关闭后链接立即失效。
  • 被分享卡片此后被编辑 / 删除时，分享页同步更新 / 失效。
FR-09 · 账户与同步

插件与 Web 端同源账户

规则

  • 插件与 Web 端使用同一账户登录（微信扫码 / 邮箱 [Assumption, TBD]）；全部对象归属该账户。
  • 收藏、判定结果、卡片编辑、复习反馈全部跨端实时同步。
  • 插件图标上显示当日待复习数徽标，作为轻量召回入口。
  • 账户注销时，删除全部数据并使所有分享链接失效（后果性动作，需二次确认）。

6共享规则与异常

R1 · 艾宾浩斯复习间隔与反馈规则（唯一权威定义）

间隔序列：D0（当天内）→ D1 → D3 → D7 → D14 → D30（天）[Assumption, TBD]。卡片生成当日即为 D0。

用户反馈间隔变化说明
忘记回到 D0，当天稍后再次出现在队列中重新学习
模糊停留在当前间隔，下次复习时间按当前间隔顺延不前进也不后退
记住进入下一间隔巩固推进

完成 D30 间隔并通过「记住」反馈后，卡片进入已巩固状态，永久退出每日队列（用户可在卡片库中手动重启复习）。FR-06 与未来的记忆宫殿（P1）都复用本规则回写复习计划。

R2 · 删除与恢复

所有删除（丢弃内容、删除卡片）一律进入回收站，保留 30 天 [Assumption, TBD] 后彻底清除；回收站内可单条或批量恢复。彻底清除不可撤销。

R3 · AI 处理重试

处理失败自动重试 1 次；仍失败进入「待重试」，用户可无限次手动重试。手动重试不重复扣减任何配额概念（配额属商业化范围，TBD）。

R4 · 原文快照留存

所有成功抓取的内容在处理时保存原文快照。卡片详情页的原文溯源优先跳原始链接，链接失效时自动降级为快照展示。快照为用户私有数据，随账户删除一并清除。

知识卡片（Card）AI 从有价值内容中提炼的核心知识的结构化呈现，是复习的基本单元
待确认AI 判定为无阅读价值、等待用户裁决的内容状态
每日队列当日到期、需要复习的卡片的有序集合
已巩固完成全部复习间隔（R1）后的卡片终态，不再进入每日队列
